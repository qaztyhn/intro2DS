## Implementation and measurement meanings

`src/tools/benchmark_protocol.py` owns the shared variant names, measurement
protocol and request-policy defaults. Comparison fixtures depend on this small
contract module rather than the execution runner.

- `src/tools/compare_runs.py`: strictly reads JSON/JSONL, revalidates files,
  adapts to existing summaries, checks conditions, exports three reports.
- `src/tools/benchmark_run.py`: executes `python -m src.main` in a separate
  checkout; writes frozen `input_ids.txt`, `config.yaml`, `benchmark.json` and
  `console.log` beside the pipeline's existing artifacts.
- `src/tools/demo_comparison.py`: small invented corpus, unordered events,
  simulated 429/retries and clearly labeled synthetic reports.
- `configs/metrics_smoke*`: shared two-ID smoke selection and request policy.

The external runner measures process launch through process exit using
`perf_counter`. This includes interpreter startup and final pipeline writes,
and uses the same boundary for all variants. Legacy runs use the recorded
`run.json.wall_seconds`; mixing the two measurement protocols suppresses
official speedups. Stage duration sums never replace pipeline wall time.

`mean_paper_processing_seconds` averages observed paper operations and inherits
their variant-specific boundaries. `wall_seconds_per_input_paper` divides total
wall time by assigned input count and is a throughput measure, not individual
paper latency. Failed papers remain in the denominator.

RAM is sampled process-tree RSS, not physical unique memory. Mean RAM uses the
existing time-weighted sample summarizer over the observed sample interval.
Disk peak is a sampled logical file-size peak under the run directory, including
logs and temporary archives; it is not an exact instantaneous filesystem peak.
Final output size covers `papers/` only. Sampling interval and coverage are in
`benchmark.json`. Sampling/monitoring adds overhead equally across variants.

Missing measurements are JSON `null`, empty CSV cells and Markdown `N/A`.
Observed zero references from successful empty responses remains zero. Missing
or failed reference outputs have no verified content count. Completion and
reference success rates use the full input set; the report also supplies counts
of observed terminal reference outcomes. No terminal reference observations
means an unknown retrieval rate. Unknown discovery lists make total expected
versions and overall version coverage unknown; known subtotals remain available.

Completion requires discovery, all known versions, reference retrieval and
actual schema/file validation. Explicit failures and unresolved papers are
separate. Confirmed `NO_TEX_SOURCE` counts as processed; unsupported/corrupt
sources do not. Schema status is recomputed without modifying the corpus;
stale saved validation is reported. Failed stage outcome counts and failed
timed operations are separate because an operation can return a business error
without raising an exception.

References are compared as multisets of normalized rows, preserving duplicate
occurrences and ignoring ordering. Metadata and source paths/bytes are hashed;
absent or failed observations are unknown, never equal merely because both
outputs are missing. These are cross-run consistency checks, not proof of
agreement with an independent ground truth. Fresh Semantic Scholar data may
change between runs; investigate differences before attributing them to code.

`benchmark_valid` verifies completion, unique run IDs, identical IDs **and
order**, environment/dependencies, request policy, credentials presence,
cold/warm mode, clean revision provenance and measurement protocol. Invalid
conditions suppress `speedup_vs_B0`; `diagnostic_wall_ratio` remains explicitly
diagnostic. Even valid conditions do not assert a quality winner. Synthetic
fixtures can pass comparability checks, but cannot establish real acceleration.

Warm runs receive a new run ID and logs, copying only their **own variant's**
fully complete cold corpus. Seed revision, environment, IDs, policy, workers and
batch size must match. Cross-variant cache reuse and cold/warm mixing are
rejected. The runner records only whether `S2_API_KEY` exists, never its value.
Use the same credential in the parent environment for all variants; credential
presence cannot prove equality of account quotas or external service load.

## Run on Google Colab, CPU only

Select **Runtime → Change runtime type → Hardware accelerator: None**. Use a
fresh runtime, Python >=3.11 (the pinned `kagglehub` dependency requires it),
and local `/content` storage during timing. Copy results to Drive only afterward.
Avoid simultaneous runs or background workloads. Do not restart/upgrade the
environment between variants.

First get this implementation into `/content/intro2DS`. Once the metrics branch
has been committed and pushed by its owner:

```python
import subprocess, sys
from pathlib import Path

subprocess.run(["git", "clone", "--branch", "feature/metrics-comparison",
                "https://github.com/qaztyhn/intro2DS.git", "/content/intro2DS"], check=True)
METRICS = Path("/content/intro2DS")
subprocess.run([sys.executable, "-m", "pip", "install", "-r",
                str(METRICS / "requirements.txt")], check=True)
```

If the branch is not published, clone `main` and upload the local updated
`src/metrics.py`, all five Metrics modules in `src/tools/`
(`benchmark_protocol.py`, `compare_runs.py`, `demo_comparison.py`,
`benchmark_run.py`, `analyze_timeline.py`), `configs/metrics_smoke.yaml` and
`configs/metrics_smoke_ids.txt` into the corresponding paths. These files are
needed only in the controller checkout; leave the target A/B checkouts intact.
Save `pip freeze` with the results for reproducibility. The runner automatically
records every installed distribution's exact version for each execution.

```python
subprocess.run(["git", "-C", str(METRICS), "fetch", "origin", "--prune"], check=True)
```

Optional credentials, set once and reused for all three runs. Without a key,
the existing pipeline uses a 3-second Semantic Scholar interval; with a key,
1 second. Shared service locks may further constrain concurrency.

```python
import os, getpass
key = getpass.getpass("S2 API key (blank for unauthenticated): ")
if key:
    os.environ["S2_API_KEY"] = key
else:
    os.environ.pop("S2_API_KEY", None)
del key
```

Use this helper to execute the three variants **sequentially**, keeping the
output run directory returned by each invocation. `--prepare-only` can inspect
the generated config without any API calls.

```python
def run_one(variant, ids, template, *, mode="cold", seed=None):
    cmd = [sys.executable, "-m", "src.tools.benchmark_run",
           "--repo", str(CHECKOUTS / variant), "--variant", variant,
           "--ids", str(METRICS / ids), "--template", str(METRICS / template),
           "--output-root", str(RESULTS), "--mode", mode,
           "--workers", "2", "--batch-size", "20" if variant == "A" else "1"]
    if seed:
        cmd += ["--warm-from", str(seed)]
    done = subprocess.run(cmd, cwd=METRICS, check=True, text=True, capture_output=True)
    print(done.stdout)
    return Path(next(line.removeprefix("Run directory: ") for line in done.stdout.splitlines()
                     if line.startswith("Run directory: ")))

smoke = {v: run_one(v, "configs/metrics_smoke_ids.txt", "configs/metrics_smoke.yaml")
         for v in ("B0", "A", "B")}
```

Exit code zero means the process completed; inspect quality too:

```python
sys.path.insert(0, str(METRICS))
```

## Coordination needed with A/B maintainers

1. `arxiv.Client` internal HTTP attempts/retries do not invoke the metrics hook.
   Observed 429/retries are lower-bound observations, never total service counts.
   Add common attempt instrumentation upstream before claiming complete counts.
2. The Metrics branch fixes reused hooks through a `for_request()` factory bound
   once by each shared HTTP invocation, outside retries. The minimal patch and
   regression evidence are in the pre-pilot review; A/B owners must integrate it.
   Old duplicate identities make comparison HTTP aggregates unknown; quality and
   timing remain reportable with a warning and suppressed official speedup.
3. Standardize paper latency boundaries or compare only wall/throughput across
   A and the other variants. Keep B workers and batch size explicit.
4. Legacy resumed logs combine executions. The reader suppresses their stage
   and resource aggregation; use the runner's fresh-run warm protocol instead.
5. Independent expected-version/content manifests described in `benchmark.md`
   were not present in this working tree. Cross-run output checks do not replace
   validation against those stored source/reference snapshots.
6. Colab itself must be verified in that runtime. Local smoke measurements are
   integration evidence, not final Colab performance claims.
7. The runner now probes effective arxiv.Client timeout and request scoping
   without network I/O. Its 40-paper launch guard blocks old targets lacking
   either capability. Configured timeout did not reach the installed library's
   GET calls; agree and implement that common policy before the pilot.
